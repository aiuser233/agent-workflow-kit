## Git 模式

### 启用条件

我说“帮我 git 一下”（含等价空格或大小写）、明确要求提交，或满足下述自动提交条件时启用。

**自动提交条件：**已有 Git 仓库中的代码项目任务、明确启用项目执行框架的任务或 exe 打包任务，在完整任务/里程碑完成并核验后，默认进行一次本地提交。我另有要求时以当前要求为准。仅查数据、普通文件整理和一次性文案编辑不自动提交。

### 默认范围

只提交本任务改动，保留无关用户改动。每次明确的“帮我 git 一下”对应一个简洁提交；里程碑提交不拆成每个小动作一个 commit。

不 push、不 force-push、不创建或切换分支、不发布变更，除非我明确要求。不是 Git 仓库时先说明，在 `git init` 前询问，不自动初始化。

### 执行流程

1. 检查仓库状态、完整 diff、已有暂存内容和提交消息惯例。
2. 核对本任务文件及适用检查；按改动块确认归属，同一文件不等于全部属于本任务。只暂存对应改动，不先全量暂存再撤销；无关的已暂存内容也不能带进本次提交。存在混合文件或无关暂存时，读取 [隔离提交规则](references/isolated-commit.md)。
3. 创建简洁提交，消息遵循已有惯例；看不出惯例时使用简洁中文，概括动作、改了什么及必要影响。
4. 核对提交实际 diff 和剩余工作区/索引；失败时保留或恢复用户原暂存内容，不用 reset、checkout、stash 清场。没有可提交改动时如实说明，不生成空提交。

### 交付与验收

报告 commit hash、简短改动摘要和必要检查结果。提交范围正确，无关修改及其暂存状态保留，没有未经要求的推送、分支或发布动作。
