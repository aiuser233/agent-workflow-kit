# 混合改动与隔离提交

同一文件存在用户改动或仓库有无关暂存时读取；工作区干净且全部改动属于当前任务时不需要隔离索引。

1. 保存开始时 HEAD、`git diff`、`git diff --cached` 与索引状态；检查未合并条目、文件模式、重命名和二进制文件。归属按任务上下文与 diff 判断，不能仅凭文件路径。已在用户文件上的修复只取本任务块。
2. 可分离的文本改动按块暂存；已有无关暂存时优先用临时 `GIT_INDEX_FILE`，从 HEAD 构建任务索引，应用经过审阅的任务补丁。该环境变量仅用于相关 Git 命令，不替换用户实际索引。二进制、重叠行或依赖用户改动无法拆开时，先准备能评审的边界方案，仅对无法决定的归属询问。
3. 提交前查看任务索引的实际 cached diff，确认无关块、敏感文件和生成物未混入；不要用 `git commit <整个混合文件>` 绕过块选择。
4. 隔离索引中的提交成功会推进仓库 HEAD，因此还须协调实际索引：以新 HEAD 为基底重放开始时的用户暂存补丁，保留其内容和 staged/unstaged 划分，避免把本次已提交内容显示为待撤销。先在另一个临时索引试重放；预计冲突应在 commit 前解决。并发改动后停止，重新核对，不覆盖当前索引。
5. 提交/hook 失败核对实际 HEAD（不能仅看命令退出码）、工作区和索引；未产生提交则保留用户开始时索引状态，本次暂存操作改变了该状态时只恢复相应索引内容。产生提交但后续协调失败则保留原索引及恢复材料，报告具体状态，不 reset HEAD 或改写用户文件。只有确认属于本次操作的临时索引可以移除。

核验看内容与分块归属，不要求推进 HEAD 后索引字节与原先一致。最终 commit 只含任务补丁；用户原暂存补丁仍暂存、未暂存补丁仍未暂存，无关文件内容不变。不能可靠实现时说明阻碍，不能把用户改动一起提交以求成功。
