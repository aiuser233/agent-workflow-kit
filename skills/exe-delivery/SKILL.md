## exe 打包模式

### 启用条件

我要求把代码交付为独立 exe、让没有 Python 的人使用时启用。只查数据、改源码或生成报告不自动打包。

### 默认范围

创建与 `src/` 平级的 `pkg/`，源码不混入构建过程文件。默认 tkinter GUI、PyInstaller `--onefile`、`pkg/build_exe.py`；已有合适 GUI 可沿用。依赖、启动性能或资源布局不适合 onefile 时允许 onedir，说明交付整目录及取舍，不强行单文件。

准确区分运行与构建：使用 exe 的电脑无需 Python；构建电脑需适配的 Windows、Python、PyInstaller 和项目依赖。记录环境和准备步骤，不承诺未配置的任意电脑直接构建。

### 执行流程

1. 检查源码真实的业务功能、输入/输出文件名、参数默认值和固定文件，不编造默认值。
2. exe 输入/资源默认相对于 exe 目录，源码运行相对于脚本/项目目录，不依赖当前工作目录。输入、输出可选择绝对路径；输出目录不假定 exe 所在目录可写，执行前检查目标和覆盖情况，不可写时保留设置并提示选其他目录。可配置日期、区间、阈值、公司名等在 GUI 可编辑。
3. 按独立业务功能分 Tab，每页独立输入、输出、参数和执行按钮；单功能单页，不按源码文件数机械分页。
   长任务在后台线程/进程执行，GUI 更新回到主线程；显示阶段进度，未知总量时用忙碌状态而不虚构百分比。执行期间禁止重复启动同一任务，异常后恢复按钮并给可操作的错误信息和必要日志路径；只有完整输出成功后才提示完成。
4. 有空白模板、匹配表、花名册、固定参照表时复制到 `pkg/templates/`，保持原名；GUI 显示固定文件名与位置。没有则不创建无用目录或固定文件区。
5. exe 优先读取同目录 `templates/`，必要回退只使用明确打入包内的资源，记录规则；没有可用资源则清楚报错，不悄悄读取个人电脑文件。
6. `build_exe.py` 相对自身定位源码、模板、临时目录和最终 exe；只增加实际必要的 `--hidden-import`、`--collect-all` 和资源，避免盲目全量打包。完成环境准备后运行脚本即可重建。
7. exe 输出到 `pkg/`。成功后只清理本次构建专用的临时目录和过程文件；删除前核实绝对目标与映射，不误删已有文件。失败保留必要诊断；源码、模板、脚本及产物保留。
8. README 增加可独立指导操作的“打包 / 交付”：GUI/Tab、路径、默认文件名/参数、模板与回退、构建/运行环境、目录、一键步骤、清理范围和核验方式。修改实现后重跑，契约变化先更新说明。
9. `.gitignore` 按项目范围排除 exe、本次构建目录、`dist/`、生成的 `.spec` 和临时文件；保留必要构建配置。提交按 local-git-commit 的适用条件执行，需要时实际加载其入口（未发现可读相邻目录），缺失则说明限制。

### 交付与验收

交付 exe（或完整 onedir 目录）、构建脚本、必要模板和说明。用真实输入比较源码与 exe 的数值或业务结果；检查默认值、GUI 响应、重复点击与异常恢复、带空格/中文路径、输出不可写反馈、产物位置、清理范围和 README 重建步骤。

仅在实际无 Python 环境运行过时声称已完成该项验证；缺少该环境或构建失败时明确报告限制。已满足本地提交条件时报告 hash，不能把未完成提交写成完成。
