# 目标清单与核验

与当前 harness 参考一起读取；本文件不授权清理，也不是跨版本数据库适配器。

每个候选记录最小字段：

| 字段 | 要求 |
| --- | --- |
| harness / version / target_id | 实际环境与目标身份 |
| resolved_path / table_key | 解析后的绝对路径与边界，或实际表/可靠主键；记录链接/重解析点映射 |
| identity | 应用正文、索引、混合日志、成果、附件、配置等真实用途 |
| deletion_evidence | 明确删除证据与交叉核实位置；不存在于列表不能单独作为证据 |
| protected_refs | 当前/运行/归档/父子/分叉/共享引用，查询范围是否完整 |
| concurrency | 占用、写入者、一致性快照和操作前复查结果 |
| action / reason | 删除指定条目、保留或跳过；理由与预期数量 |
| verification | 事务/结构/保护对象核验及实际结果；适用备份位置 |

共享成果或附件即使目标会话已删除仍保留；一份文件兼具正文副本与成果用途时按受保护用途处理。混合缓存只能删除可可靠分离的授权条目，无法解析则跳过。清单仅记元数据，不复制待删正文。

数据库脚本先在一致性副本或最小模拟库验证关联和删除顺序，不以真实库试错；模拟至少包含目标、现存/归档、父子和共享引用，核对目标专属记录、受保护记录及外键完整性。副本有敏感内容时沿用备份保护和去留规则，不额外导出正文。

真实修改前只读核对 schema、命中数量、引用与并发状态；任何证据变化都使原计划失效，需要重新核对或跳过。Codex 的离线条件与 ZCode 的有条件并发要求各自遵循，锁等待成功不等于归属或回写安全。

修改后定向检查目标结果、保护引用、JSON 结构与数据库 `quick_check`，适用时检查外键。只读核验、模拟通过、真实删除和无法核验分开报告；模拟通过不代表当前宿主版本已实测。
