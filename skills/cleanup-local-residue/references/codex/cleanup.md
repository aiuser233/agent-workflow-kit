## 已删除项目/对话的本地残留清理模式

### 启用条件

只有我明确要求“清理已删除项目/对话的本地残留”或等价行动时，才执行一次。上下文清楚时“按残留清理规则再执行一次”也有效。讨论、审阅、保存规则，普通项目删除、归档或聊天结束均不触发清理。

触发后，授权直接删除确认归属于删除目标的本地对话正文、历史输入、草稿、索引、关联状态及相关日志/缓存记录。归属明确且安全的操作不逐项重复询问；工具确认要求仍须遵守。不能确认或不能安全处理时跳过，继续其他目标，再报告剩余项。

### 默认范围与保护对象

1. 仅当前 Windows 用户的本地信息。保护当前聊天、现存项目、未删除或运行中的会话及仍被保护对象引用的数据；不删除云端聊天。
2. **归档不等于删除。** 归档会话，包括 `archived_sessions` 和数据库 `archived=1` 的记录，不能仅因归档而删除。
3. **保留之前生成的所有文件和代码。** 项目目录、Git 仓库、源码、原始文档、下载数据、模板、报告、图片、截图、可视化、导出和交付成果均保留，包括 `Documents\Codex`、`work/`、`output/`、`outputs/`。即使含旧聊天正文或 ID，也不凭本次授权删除或改写。
4. 用户附件和附件副本默认保留，另有明确具体授权才清理。不能将成果、附件等改称“对话副本”绕过保护范围。
5. 保护凭据、Cookie、登录、配置、技能、插件、运行时、程序和全局 `AGENTS.md`；不整目录删除 `.codex`、浏览器配置或整库删除 SQLite。
6. 不退出、强杀或重启应用，不中断其他聊天、任务和当前会话。占用数据先跳过并说明需关闭哪个应用。
7. 不擦除磁盘/未分配空间、执行 SSD 安全擦除、清空整机回收站、删还原点或操作云端/备份服务。应用记录删除不等于服务器或底层可恢复字节清除。

### 执行流程

#### A. 定位与保护清单

确定真实用户目录及 `CODEX_HOME`，未设置时检查用户目录 `.codex`，不照搬其他电脑用户名。

优先核实全局状态及 `.bak`、`session_index.jsonl`、`sessions`、`archived_sessions`，当前版本的 `state_*`、`thread_history_*`、`logs_*`、`memories_*`、`goals_*`、`queue_*` 数据库和 `sqlite/`；必要时检查 Codex Roaming 网页存储、Local 日志和 Store LocalCache。版本、包名、表结构及独立 ChatGPT/Work 目录实际发现，不假定存在。

浏览器、附件、可视化、`Documents\Codex` 和临时目录仅根据具体 ID/引用/路径定向核实，受保护文件保留。不扫描全盘、遍历插件源码或全文搜索全部用户文档。检查映射与文件身份，避免同一数据重复处理、统计。

只读获取现存项目、会话、归档、运行任务及当前聊天身份；接口有分页时获取完整范围，不能完整获取时说明限制，不能把未列出当作删除证据。

#### B. 核实删除目标

1. 依据明确删除证据，交叉核对项目记录、索引、数据库和 rollout 元数据。`prompt-history`、`composer-prompt-drafts-v2`、`codex-writing-block-deleted-thread-v1:<ID>` 等只是可能线索，不是稳定官方接口或单独删除证明。
2. 确认已删除、未归档、非当前/运行会话，且没有保护对象引用后，才能进入目标清单。索引缺失、文件旧、空目录或侧边栏移除均不足以确认删除。
3. 核对分叉、续接、迁移和子代理关系，文件名可能含主 ID 与分叉 ID；不能因为 ID 不在某张表就视为删除。
4. 清单冲突或身份/引用无法核实则保留，说明原因；混合存储仅移除可安全分离的目标条目，不靠名称或内容猜测归属。

#### C. 针对性处理

**状态、历史、索引：**仅移除确认目标的历史输入、草稿、标题、路径/项目关联、客户端绑定、浏览器映射和索引；检查对应备份及临时状态。相似文字不构成关联证据。JSON 保留无关字段、校验结构，写回前检测并发变化，变化则重读或跳过，不覆盖新状态；不能确认可移除的删除标记保留为最小元数据，避免旧会话重新出现。

**内部正文文件：**仅删除确认专属于目标且未被保护会话引用的应用内部 rollout、历史正文副本。共享文件按条目操作，无法安全分离则跳过。递归操作前核对绝对路径、边界和映射，使用同一 shell 原生操作，不跨 shell 拼接删除命令。

**SQLite：**有明确适用的本地删除接口则优先用，不调用删除云端或现存会话的接口。按实际表和可靠关联字段定位正文、turn/item、历史投影、日志、记忆、目标、队列和项目关联，仅处理专属记录。确认数据库未被应用使用且不会并发写入后才直接修改，不抢锁强改现用库；使用事务、参数化语句并维护引用一致性。不整库删除、不手删现用 `-wal`/`-shm`。仅离线且适合维护时按实际需要选择 checkpoint、`secure_delete` 或 `VACUUM`，不机械全跑；不能处理旧页/WAL 时报告。

**日志和网页缓存：**先确认目标 ID、路径或正文实际存在，优先清理对应记录；仅含确认目标、可丢弃且非成果文件时可整文件删除。混合日志保护其他记录，不能安全修改则跳过。浏览器仅处理可靠定位的目标数据，不清空所有站点或登录状态。`conversationId`、`messages`、`author` 等通用词可能只是代码，不能当正文证据；不能可靠解析 IndexedDB、LevelDB 或压缩缓存时保留，不替换原始字节。

#### D. 定向复核

检查已处理目标、JSON/索引有效性、事务结果和保护对象是否保留；无法复核单列。不要为报告将待删正文、输入或附件另存到新导出或日志，避免新副本；摘要只记录必要 ID、路径、数量和原因，不复制正文。

### 交付与验收

分别报告实际清理目标及记录/文件数量、保留的归档与文件成果、占用或归属待确认项、最小删除标记和未能安全处理的本地残留。实测才报告释放空间，未找到、跳过、删除分开。

验收：目标有交叉核实证据；仅处理授权信息；归档、现存会话、文件/代码/附件及配置保留；未损坏混合存储、未中断应用；剩余项具体可定位。不能承诺已清除云端或底层可恢复数据。
