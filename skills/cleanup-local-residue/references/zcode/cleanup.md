## 已删除项目/对话的本地残留清理模式

### 启用条件

只有我明确要求“清理已删除项目/对话的本地残留”或等价行动时，才执行一次。上下文清楚时“按残留清理规则再执行一次”也有效。讨论、审阅、保存规则，普通项目删除、归档或聊天结束均不触发清理。

触发后，授权直接删除确认归属于删除目标的本地对话正文、历史输入、草稿、索引、关联状态及相关日志/缓存记录。归属明确且安全的操作不逐项重复询问；工具确认要求仍须遵守。不能确认或不能安全处理时跳过，继续其他目标，再报告剩余项。

### 默认范围与保护对象

1. 仅当前 Windows 用户的本地信息。保护当前会话、现存项目、未删除或运行中的会话及仍被保护对象引用的数据；不删除云端同步的会话。
2. **归档不等于删除。** `session.time_archived` 非空的归档会话，不能仅因归档而删除。
3. **保留之前生成的所有文件和代码。** 项目目录、桌面项目文件夹、`workspace\default`、Git 仓库、源码、原始文档、下载数据、模板、报告、图片、截图、可视化、导出和交付成果（如 `output/`、`outputs/`、`pkg/`）均保留。即使含旧聊天正文或 ID，也不凭本次授权删除或改写。
4. 用户附件和附件副本默认保留，另有明确具体授权才清理。不能将成果、附件等改称“对话副本”绕过保护范围。
5. 保护凭据（`v2\credentials.json`）、登录态、配置（`cli\config.json` 及 `v2` 根目录各配置/状态文件）、长期记忆（`cli\memories\`）、技能、命令、子代理、插件、运行时、现存工作区的检查点和全局 `AGENTS.md`；不整目录删除 `.zcode`，不整库删除 SQLite。
6. 不退出、强杀或重启应用，不中断其他聊天、任务和当前会话。占用数据先跳过并说明需关闭哪个应用。
7. 不擦除磁盘/未分配空间、执行 SSD 安全擦除、清空整机回收站、删还原点或操作云端/备份服务。应用记录删除不等于服务器或底层可恢复字节清除。

### 执行流程

#### A. 定位与保护清单

确定真实用户目录及 ZCode 数据目录 `%USERPROFILE%\.zcode`，不照搬其他电脑用户名。核心是 `cli\`（会话与命令行层）和 `v2\`（桌面客户端层）两块。优先核实以下位置，以实际发现的版本和表结构为准，不假定存在：

- 会话主存储 `cli\db\db.sqlite`：`session`（主键 `id`，`time_archived` 标记归档，`parent_id` 标记子代理关系）、`message`、`part`、`todo`、`session_entry`、`permission`、`input_history`、`model_usage`、`turn_usage`、`tool_usage`、`session_input` 等表，其余表多以 `session_id` 关联；
- 客户端任务列表 `v2\tasks-index.sqlite`：`tasks.task_id` 即 `sess_<id>`，`task_group_view_node_orders.node_key` 亦可能引用；
- 旁路会话文件：`cli\exec\sess_*`、`cli\exec\bash-startup\sess_*`、`cli\artifacts\sess_*`、`cli\image-cache\sess_*`、`cli\agents\sess_*`、`cli\rollout\model-io-sess_*.jsonl`；
- 检查点 `v2\checkpoints\<16位哈希>\`：`state.json` 的 `workspacePath` 标明所属工作区，哈希为工作区路径转小写后 SHA-256 的前 16 位，归属以 `workspacePath` 为准；
- 日志 `cli\log\zcode-日期.jsonl`、`v2\logs\日期.log`；长期记忆 `cli\memories\projects\<项目哈希>\`。

附件、图片缓存和临时目录仅根据具体会话 ID、引用或路径定向核实，受保护文件保留。不扫描全盘、遍历插件源码或全文搜索全部用户文档。检查映射与文件身份，避免同一数据重复处理、统计。

只读获取现存项目、会话、归档、运行任务及当前会话身份；当前对话绑定哪个 session 以运行环境信息为准，不能完整获取时说明限制，不能把未列出当作删除证据。

#### B. 核实删除目标

1. 依据明确删除证据：项目工作区目录已在磁盘删除，且客户端任务索引已无对应任务或经我明确确认，再交叉核对 `cli\db\db.sqlite` 会话记录。`input_history`、`session_entry` 及 rollout 文件名只是存储线索，不构成单独删除证明。
2. 确认已删除、未归档、非当前/运行会话，且没有保护对象引用后，才能进入目标清单。索引缺失、文件旧、空目录或客户端列表不可见均不足以单独确认删除。
3. 核对 `session.parent_id` 父子关系与子代理会话（`sess_subagent_*`）：主会话删除时按归属一并处理其专属子会话数据；不能因为 ID 不在某张表就视为删除或保留。
4. 清单冲突或身份/引用无法核实则保留，说明原因；混合存储仅移除可安全分离的目标条目，不靠名称或内容猜测归属。

#### C. 针对性处理

**状态、历史、索引：**仅移除确认目标的历史输入、草稿、标题、路径/项目关联、任务索引条目和死工作区的检查点目录；检查对应备份及临时状态。相似文字不构成关联证据。JSON 保留无关字段、校验结构，写回前检测并发变化，变化则重读或跳过，不覆盖新状态；不能确认可移除的删除标记保留为最小元数据，避免旧会话重新出现。

**内部正文文件：**仅删除确认专属于目标且未被保护会话引用的 rollout（`cli\rollout`）、应用内部正文缓存和会话执行目录（`exec`、`exec\bash-startup`）。`artifacts`、`image-cache` 仅为候选位置，成果、附件、图片及副本不因位于这些目录而可删除；逐项核实文件身份。共享文件按条目操作，无法安全分离则跳过。递归操作前核对绝对路径、边界和映射，使用同一 shell 原生操作，不跨 shell 拼接删除命令。

**SQLite：**按实际表和可靠关联字段定位正文、分片、待办、输入历史、用量记录和会话记录，仅处理专属记录；注意 `session` 表主键为 `id`，其余表多用 `session_id` 关联。原规范允许应用运行中有条件并发访问，但须设置 busy_timeout 等待锁，核实保护引用并防止应用回写冲突；无法证明安全则跳过。锁等待不等于并发安全，不抢锁强改现用库，不手删现用 `-wal`/`-shm`；使用事务、参数化语句并维护引用一致性。删除前用 SQLite backup API 或等价一致性机制备份整库（包含已提交 WAL 数据）到明确路径并报告位置，不简单复制活动主库；由我确认结果后再自行删除备份。完成后仅在维护条件允许且实际需要时 `VACUUM`，并跑 `quick_check`；不能处理旧页/WAL 时报告。

**日志与客户端状态：**日志按日期分文件（`cli\log`、`v2\logs`），仅含确认目标、可丢弃且非成果文件的旧日志可整文件删除，保留当天及仍在写入的文件。`v2` 根目录的 `bot-state*.json` 等客户端状态文件运行中可能持有内存态并在退出时回写，不能确保按条目安全修改时整体跳过并说明。`task_id`、`session_id`、`title` 等通用字段不能当正文证据；不能可靠解析的缓存保留，不替换原始字节。

#### D. 定向复核

检查已处理目标、JSON/索引有效性、事务结果和保护对象是否保留；无法复核单列。不要为报告将待删正文、输入或附件另存到新导出或日志，避免新副本（整库备份除外，且须报告位置由我决定去留）；摘要只记录必要 ID、路径、数量和原因，不复制正文。

### 交付与验收

分别报告实际清理目标及记录/文件数量、保留的归档与文件成果、占用或归属待确认项、备份位置和未能安全处理的本地残留。实测才报告释放空间，未找到、跳过、删除分开。

验收：目标有交叉核实证据；仅处理授权信息；归档、现存会话、文件/代码/附件及配置保留；未损坏混合存储、未中断应用；剩余项具体可定位。不能承诺已清除云端或底层可恢复数据。
