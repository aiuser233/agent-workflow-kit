## 数据报告模式

### 启用条件

我要求正式数据报告、带来源报告或可复现 HTML 报告时启用。普通文字答复、只查数据不自动进入本模式；指定 Word、PDF 或其他格式时优先采用指定格式。

### 默认范围

先确定材料、指标口径、时期、读者、结构和验收。默认两项主要交付物：单一自包含 HTML 和单一入口脚本。必要的原件、来源索引、数据字典等复现材料另行保留，不受“两项”限制。图表仍遵循核心可视化开关，仅在用户明确要求时生成。

### 执行流程

1. 开工前列出简洁材料清单：数据文件、参考材料及各类结论对应来源。清单用于说明依据，不形成额外审批；澄清遵循 clarify-requirements 的适用条件。
2. 区分信息性质：`[F]` 为可核验事实；`[C]` 为按可追溯输入和公式实际计算的结果；`[I]` 为没有直接出处的推断；`[U]` 为未知或无法验证。不能用猜测补齐未知。
3. 正文默认只写 `[F]` 和核验后的 `[C]`，计算结果清楚注明性质。`[I]`、`[U]` 默认不写；我要求保留时放在独立“推断与未证实”附注。来源缺口不能补齐的事实句删除。
4. 每个事实句和计算结论带句尾上标 `[1]`、`[2]` 等，关联页尾“来源批注”：网络给具体链接和访问日期；本地材料给文件名及页码/工作表/字段/记录或段落；计算值给输入来源、公式和必要舍入规则。
5. 同一来源复用编号，一句含多来源事实时列齐编号或拆句，表格使用清晰来源列或表注。链接可点、位置可查，不拿机构首页替代具体出处。
6. 脚本一次完成读取、整理、计算和生成/更新报告，数字来自实际运行，不手填统计结果。数据或规则变更后重跑即可，不手工修改生成 HTML；数据处理时读取 source-data-research 的适用规则。
7. HTML 不依赖外部 CDN 或在线资源才能阅读，表格内嵌，要求的图表内嵌。项目中脚本放 `src/`、报告放交付目录；独立便携交付时可同目录，路径相对于脚本或项目目录，沿用 project-workflow 的适用约定。
8. 默认脚本生成后打开浏览器，提供关闭自动打开的参数；无人值守或无法打开时报告路径。需要无 Python 环境使用时组合 exe-delivery，不自动打包。

### 交付与验收

交付 HTML、入口脚本及必要复现材料，记录依赖、运行方法和来源。核验事实/计算分级、逐句批注、编号、离线阅读、脚本重新生成及数值一致性；无法运行或验证时明确说明，不能声称全部通过。
