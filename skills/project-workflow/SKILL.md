## 项目管理模式

### 启用条件

任务涉及持续维护或需要复现的代码、数据、文档项目，或我明确要求按项目框架执行时启用。优先沿用现有目录、技术栈和约定，不为套模板大规模搬动文件。

### 默认范围

新项目按需使用以下结构，不创建无用途的空目录：

```text
raw/       原始材料与来源索引；原件内容不修改、不覆盖
src/       源代码、脚本、配置和依赖说明
output/    生成物、结果和报告
docs/      方法、分析、清洗和核验记录
README.md  项目状态、口径和复现入口
```

数据任务增加 `data/cleaned/`，打包任务增加与 `src/` 平级的 `pkg/`。环境约定使用 `outputs/` 或其他交付目录时沿用，并在 README 说明对应关系。可以更新来源索引，不能借此修改原始文件。

### 执行流程

1. 检查现有文件、项目说明和工作状态，再决定需要创建或更新的内容。
2. 按以下顺序维护 README，未知信息如实标明：
   - 一句话说明项目做什么；
   - 背景、使用对象、关键决策和取舍理由；
   - 技术栈、版本、依赖及必要环境；
   - 约束和明确不做的事项；
   - 指标定义、单位、术语和日期口径；
   - 最近 5 条重大变更：日期、改了什么、为什么；
   - 待办、未完成项、当前卡点和下一步；
   - 目录说明、运行与复现步骤，适用时附数据来源或打包规则。
3. 完成有意义的步骤后更新相关记录；完整任务或里程碑完成时更新变更日志和待办，新文件或目录同步更新目录说明。
4. 使用相对于脚本或项目目录的路径，不写死个人电脑路径，不依赖启动时的当前工作目录；允许用户明确选择的输入/输出路径。
5. 按改动影响运行必要检查。已有测试优先复用，不为低影响、可逆的小改动机械新增测试；未核验的部分说明限制。
6. Git 是否提交统一遵循 local-git-commit 的适用条件，不为每个小动作产生提交。

当我说“请先读 README.md 和 git log --oneline -10，然后继续 {任务}”时，先读 README、适用项目说明，并在仓库中核对最近提交、当前状态及相关文件。README 和日志帮助恢复上下文，但不能替代实际检查；关键缺口才继续问。

### 交付与验收

交付本次改动及更新后的项目说明。README 应能指导继续工作和复现实际已完成步骤；目录与说明一致，原件及无关改动保留，检查结果和待办准确。一次性任务不强制建立无必要的 README。
